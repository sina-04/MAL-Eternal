# Security policy

## Supported version

Security fixes are applied to the latest revision of the `main` branch.

## Reporting

Do not open a public issue containing credentials, personal achievement
records, authentication details, or an exploitable vulnerability. Use
GitHub's private vulnerability-reporting feature when it is available for this
repository.

Reports should include the affected route or component, reproduction steps,
impact, and a minimal proof of concept without real personal data.

## Data boundaries

The repository must never contain production D1 contents, personal achievement
records, deployment secrets, cookies, or private account identifiers. The
Render preview uses ephemeral storage and is not a durable home for personal
data.
